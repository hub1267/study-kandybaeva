## Тест-кейсы

Предусловие: сервер запущен, учебная база заполнена. Результат «не проверен» означает, что фактическое выполнение ещё не зафиксировано.

| № | Действия | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | Открыть главную страницу | Заголовок «Заказы» и форма входа | Соответствует |
| 2 | Ввести admin и нажать «Войти» | Показаны ФИО, роль администратора и список заказов | Соответствует |
| 3 | Ввести неизвестный логин и нажать «Войти» | Сообщение «Пользователь не найден» | Соответствует; при предыдущем входе прежняя роль остаётся активной |
| 4 | Войти как admin, открыть заказ № 1 | Показаны позиции и итоговая сумма 15 000 ₽ | Соответствует |
| 5 | Войти как manager, нажать «Выйти» | Имя заменяется на «Гость», список скрыт | Соответствует |

## Баг-репорт

**Заголовок:** API изменения заказа доступен без проверки роли на сервере.

**Окружение:** локальное учебное приложение на macOS, Python HTTP server и SQLite.

**Предусловие:** известны номер учебного заказа и номер позиции.

**Шаги:** отправить запрос POST к `/api/order/update` с корректными id заказа, датой и списком удаляемых позиций без авторизации.

**Ожидается:** сервер проверяет, что запрос выполнил администратор, и отклоняет запрос без действующей сессии.

**Фактически:** на отдельной временной базе выполнен POST без cookie с телом `{"id":1,"date":"2026-10-06","removed":[1]}`. Ответ — HTTP 200 и `{"ok":true}`; количество позиций заказа стало 0, остаток товара увеличился с 8 до 10. В учебном условии вход упрощён до логина, но серверная проверка прав необходима для реальной системы.

**Серьёзность:** высокая для реального сервиса; приложение используется только локально на учебных данных.

## Проверка формы входа

Позитивный сценарий admin выполнен. Неизвестный логин вызывает сообщение «Пользователь не найден». Проверка проводилась после входа администратором: прежняя роль при ошибочном входе сохранилась, что может вводить в заблуждение. Пустой ввод браузер блокирует сообщением о необходимости заполнить поле. Строка из пробелов и логин из 300 символов отправляются на сервер и получают ответ «Пользователь не найден»; отдельные сообщения о формате или длине не предусмотрены.
